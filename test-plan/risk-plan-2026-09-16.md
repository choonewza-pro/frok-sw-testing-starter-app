## 🎯 Recommended Testing Approach

### 🔴 Critical — Test Immediately

- **Auth & Admin Access Control** — มี session state (anonymous → authenticated → expired) + role enum (admin/user) → **STT** สำหรับ transition + redirect (`/login` vs `/`). ส่วน email/password/name → **EP** (รูปแบบอีเมล, รหัสผ่าน ≥8, ชื่อ 2–50).
- **Admin Product CRUD** — มี delete guard workflow (exists? → มี order_items อ้าง? → 404/409/delete) → **STT** + ฟิลด์ validation ครบ → **EP** (ชื่อ/category) + **BVA** (price >0 ถึง 10M, ชื่อ 1–255, parseNumberInput เจอ comma/space/NaN).
- **Order Management** — มี status (`orders.status` เป็น String เปิด) + limit param → **STT** ถ้ามี workflow สถานะ + **BVA** สำหรับ `parseOrdersLimit` และ `total_amount`/`quantity`.

### 🟠 High — Test This Sprint

- **Product Catalog** — `q` (trim, array→"") + `page` (NaN→1, <1→1) → **EP** สำหรับ q + **BVA** สำหรับ page/skip/totalPages (0 สินค้าต้องได้ 1 หน้า, pageSize≤0→1).
- **Course Catalog** — เสี่ยงสุดคือ external API เปลี่ยน schema/timeout → **EP** (valid/invalid JSON, ขาด field, picture ไม่ใช่ URL, response.ok=false, throw). ไม่ต้อง BVA มากยกเว้น timeoutMs.
- **Contact Us** — honeypot branch (undefined/"" vs มีค่า) → **EP** + ความยาวฟิลด์ → **BVA** (name 2/100, subject 3/150, message 10/2000, email format) + sender null/fail/throw.
- **Cart** — pure function ที่ test ง่ายสุด คุ้มสุด → **BVA** (qty 0/ลบ → ลบออก, บวกซ้ำ) + **EP** (productId ไม่มี, clearCart, persist key `skill-cart`).
- **Reporting** — สูตรคำนวณล้วน → **BVA** (orderCount=0 → avg=0 ไม่ใช่ NaN, revenueSum null→0) + **EP** (period/day-key enum).

### 🟢 Low — Defer

- **Static Home/About** มี negligible risk. Test ทีหลังได้.

## 🔧 Technique Guide

| Technique | When to Use | swe-test-engineer keyword |
|-----------|-------------|--------------------------|
| **BVA** | Numeric/time inputs with ranges (price, qty, page, limit, ชื่อ 2–50, message 10–2000) | "boundary value" |
| **EP** | Enum, dropdown, role, boolean, text type inputs (email, role, category, honeypot, status) | "equivalence partitioning" |
| **STT** | Status fields, approval flows, state machines (session, delete guard 404/409, order status) | "state transition" |
| **Mixed** | Feature has both range inputs AND enum/workflow inputs | List each condition separately |
